# OPT-01：最新思考与完整记录入口

状态：未实施。产品方向已接受。优先级 P0。分片 01A 修复窗口，01B 完成记录访问。

## 问题与证据

CodeBuddy 在 `src/agent/codebuddy/adapter.ts` 复用 `src/agent/claude/stream-json.ts` 的 translator。thinking 事件进入 `src/card/run-state.ts`，内容不断追加；`src/card/run-renderer.ts` 使用 `REASONING_MAX = 1500` 和 `slice(0, max)`，固定保留开头。

已通过真实 reducer/renderCard 复现：内容长度 1600 → 1623，渲染 JSON 完全相同，最新标记不可见。活动/完成思考面板共用该路径。`/last` 只保存正文，不能作为完整思考入口。

## 用户可见行为

### 01A 最新窗口

- 超过窗口后保留尾部，新思考到达后能出现在可见正文。
- 明确提示“显示最近思考，前文已隐藏”，不能用省略号冒充完整内容。
- 短内容无需隐藏提示；不改变原始记录。
- 以 Unicode 安全方式确定边界；尽量按行/段落截取，处理跨边界 Markdown 与代码块。窗口预算和标记文字一起受控。
- 活动和完成面板使用一致的窗口语义。切换为完成态不意味着恢复显示完整内容。

### 01B 完整记录

- 查询内容等于桥接器收到的思考内容，保持顺序；不包括未经接收、推测或补写的内部推理。
- 用户可以从头到尾访问记录；不能只返回末尾固定字符，也不能要求去服务器 grep 日志。
- 下一轮运行完成后，旧记录入口不能静默切换到新记录。若只支持最近一轮，应将范围明确写在入口文案和回复中；推荐入口绑定 runId。
- 无思考、进行中、正常结束、失败/中断后的部分记录、已过期、无权访问，应有不同的反馈。
- 查询和分页仅操作记录，不触发 Agent 新运行，不中断当前运行。

## 候选接口与权衡

推荐：`/thinking` 展示当前 Scope 最近运行的记录摘要和第一页；`/thinking <runId> [页码]` 查询指定运行。卡片中的入口携带 runId，分页保留同一身份。具体命令拼写和按钮形态可按仓库现有模式调整。

简化方案：只保存最近一次运行并使用 `/thinking [页码]`。实现较小，但旧卡片只能指向“当前会话最近记录”，必须明确标注；用户尚未单独接受这一限制，实施前应说明取舍。不要在一个长期保留的完成卡片上写“查看本次完整记录”却只保存最新一份。

## 数据与边界

- 推荐记录身份：Profile + Scope + runId；元数据包括 Agent、开始/结束时间、终态、思考是否完整、可读内容长度。
- 生命周期：运行中收集 → 终态保存 → 查询；保存失败时不能展示“已保存”或可用的历史按钮。
- 记录应在用户数据目录，不能写入仓库。复用现有原子写入/锁约束；不要把所有历史无界塞进 sessions.json。
- 保留期、单运行容量、总容量和过期清理是待确定的产品参数。优先沿用已有配置；新增时记录默认值和取舍，不凭空声称永久保存。
- 设容量上限时，必须显式表示部分记录及缺失范围。不能在“完整”名义下静默截断；必要时分片落盘。
- 查询按当前用户的实际访问权限和 Scope 校验。runId 不是授权凭证；不能靠猜路径或传入其他 Scope 读取数据。
- 不改写 `/last` 的正文含义。下一轮无 thinking 时，`/thinking` 的“最近运行”语义应避免泄露上一轮内容并造成误解。
- 原始记录与卡片预览分离，卡片隐藏不应造成记录丢失；展示时不要将原始内容当作可信指令或卡片 JSON。

## 验收

- 1499、1500、1501 以及 10 万字符样例追加唯一尾部标记，可见窗口持续变化，内容受预算限制。
- 中文、emoji、组合字符、换行与未闭合代码块不会导致乱码或不可用卡片。
- 01A 测试确认原始思考内容未被窗口处理修改。
- 经 CodeBuddy translator → 状态 → 完成保存 → 查询入口，所有页拼接后与收到的文本完全相同。
- 下一轮运行、无思考运行、重启、会话重置、记录过期分别满足已选定且文档化的语义。
- 查询其他 Profile/Scope 被拒绝；旧卡片身份、失效按钮和多次分页正确处理。
- 记录保存失败不阻断最终答复，但历史入口反映实际失败，不假称成功。

## 不做

本任务不增加通用任务数据库，不改 Agent 权限，不迁移所有正文日志，不处理所有卡片调度问题，也不承诺获取上游隐藏推理。
