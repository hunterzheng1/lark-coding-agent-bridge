# 优化方案与 Agent 执行入口

日期：2026-09-17。调查基线：`003f01e`，版本 `0.3.17`。

本目录用于将优化工作交给其他 Agent 逐项实施。本次只交付文档，没有实施产品改动。接手 Agent 应重新核查当前代码，不能假定基线之后没有变化。

## 授权与决策状态

- **已接受的产品方向**：运行中显示最新思考，完成后通过独立入口查看完整已接收的思考记录。
- **已确认的现场现象**：CodeBuddy 卡片「🧠 思考中」和「🧠 思考完成，点击查看」达到一定长度后不再显示新增内容。
- **已复现的源码缺陷**：思考累积增长，渲染却固定保留前 1,500 个 UTF-16 code unit。
- **尚未确认**：现场运行安装包版本；历史入口的具体交互、保留范围和存储方案；其余优化的产品取舍。
- **当前指令**：只生成优化文档，不实施。本文档不是启动全部任务、修改生产配置、部署或发布的授权。其他 Agent 收到具体任务后，再按当时指令和仓库规则执行。

`/thinking [页码]` 是候选命令，不是用户已经接受的接口。也不能将“完整记录”悄悄缩减为“固定长度摘要”或只能访问最后一页。

## 统一词汇

| 术语 | 本文含义 |
|---|---|
| Scope | 消息共享执行顺序与上下文的范围；私聊/普通群通常为 chat，话题群为 chat + thread |
| 会话 | 多轮交互间保持的 Agent 上下文；不等同于某一次运行 |
| 运行（run） | 一次提交到终态的 Agent 执行，由 runId 区分 |
| 思考记录 | 桥接器实际收到的上游 thinking/reasoning 内容；不承诺上游未公开的内部推理 |
| 进度 | 实际事件支持的活动或阶段，不凭工具数量猜完成百分比 |
| 投递状态 | 某个版本的展示是否成功送达飞书；与 Agent 是否运行分开 |
| 执行记录 | 正文、工具事件、思考记录等的统称；OPT-01 只要求思考记录，扩展全集需另定范围 |
| 完成凭据 | 有来源的检查结果、改动与产物；进程正常退出本身不能证明用户目标完成 |

## 必须保留的架构边界

- `cli → bot → runtime/agent → card/policy/session`；公共 bot/card 不引入某个 Agent 的内部实现。
- 同一 Scope 至多一个运行；不同 Scope 的并发通过现有进程池管理。
- 复用 RunPolicy、工作目录真实路径、权限上限、策略指纹和回调验证。
- 用户数据位于 Profile 对应的 `~/.lark-channel` 或覆盖目录；配置/秘密写入遵循锁约束，持久化复用原子写入设施。
- 不能把会话可恢复、入站消息可恢复、外部副作用可重放视为同一件事。
- 竞品的产品模式可以借鉴；若复制代码或资源，应另外核对许可证与署名要求。
