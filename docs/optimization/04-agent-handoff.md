# Agent 交接模板

把下方模板中的任务编号替换后发给接手 Agent。建议一次分配一个任务或切片。

## 实施任务模板

```text
请实施 lark-channel-bridge 的 OPT-XX（或指定切片）。

先读取仓库 AGENTS.md，以及：
- docs/optimization/README.md
- docs/optimization/02-roadmap.md
- docs/optimization/tasks/OPT-XX 对应规格
- docs/optimization/03-verification.md

研究基线为 003f01e，请重新核查当前源码、git 状态与已完成工作。
若 .codegraph 存在，按 AGENTS.md 先用 CodeGraph 定位。

本次只实施上述任务，不自动开展其他路线图任务。
保留用户与其他 Agent 的现有改动，遵守运行/权限/持久化边界。
先建立能复现实际缺陷或缺失行为的测试，再实施最小改动。
产品方案中的候选接口可按现有架构调整，但不得悄悄缩减验收行为。
需要改变已接受的交互语义、历史范围或权限边界时，先说明具体取舍。

完成后更新该任务文档的实施状态和证据，说明：
行为变化、测试结果、兼容性、限制、剩余工作以及 Git 状态。
提交与推送遵守仓库当前规则；部署、服务重启和包发布需要对应授权。
```

## 只评审方案模板

```text
请只评审 docs/optimization/tasks/OPT-XX 对应规格，不实施。
对照当前源码，检查事实是否仍成立、依赖是否准确、验收是否充分。
指出过度设计、遗漏的失败路径及更小的实现选择。
把已确认事实、推测和产品取舍分开；不要仅因为竞品有某功能就要求复制。
```

## 每项任务的交接记录

| 字段 | 填写要求 |
|---|---|
| 任务与切片 | 例如 OPT-01A，不写笼统的“优化完成” |
| 基线与工作分支 | 执行时 HEAD；遵守仓库 Git 工作流 |
| 前置条件 | 已完成依赖、缺失权限/资料 |
| 所选设计 | 用户可见语义，候选方案的实际选择 |
| 修改范围 | 产品文件、测试、文档 |
| 验证证据 | 命令与结果，未执行的现场检查 |
| 状态 | 未开始/实施中/待验证/已完成/有阻塞 |
| 剩余事项 | 具体缺口，不能隐去失败用例 |

## 多 Agent 协作注意

本目录供顺序交接使用，不要求自动启动并行 Agent。若以后明确分配并行任务，需先按文件划分所有权；`src/bot/channel.ts`、`src/agent/types.ts` 和 Session/记录接口是高冲突区域，应由一方协调。

任务文档中的“建议”不等于用户已选择全部方案。尤其不能从 OPT-01 的接受推导出数据库迁移、多平台扩张、自动审批或多 Agent 调度已获批准。
